# قواعد مشروع غيث (Ghaith Frontend)

المشروع: نظام محل ملابس إسلامية — واجهتين: **أدمن** (داش بورد، مبيعات،
منتجات، تصنيفات، مخزون، موردين، مستخدمين، مصروفات، خصومات، تقارير) و**كاشير**
(بيع، فواتير، استبدال/استرجاع، مديونيات، إغلاق وردية، مصروفات). كله RTL،
Vanilla JS (ES Modules)، بدون build step إجباري، بدون framework.

## القاعدة الذهبية

**كل حاجة بتتحط في مكانها الصح ومفيش تكرار.** قبل ما تكتب أي كومبوننت أو
CSS class جديدة، دور الأول في `assets/css/components/` و `src/components/`
لو موجود حاجة شبهها — استخدمها أو وسّعها، ما تعملش نسخة جديدة بنفس الوظيفة.

## بنية المجلدات (متتغيرش)

```
assets/css/base/        متغيرات، reset، تايبوجرافي — تتغير نادرًا جدًا
assets/css/components/  عناصر مشتركة (بطاقات، جداول، فورمز، مودال...)
assets/css/layout/      الهيكل العام + الـ breakpoints
src/core/                router.js, api.js, store.js, utils.js — منطق مركزي
src/components/          كومبوننتات JS قابلة لإعادة الاستخدام
src/pages/<page>/        كل صفحة: <page>.html + <page>.js + <page>.css فقط
mock-data/                بيانات وهمية بنفس شكل رد الـ API الحقيقي
```

لما تضيف صفحة جديدة: اعمل فولدر تحت `src/pages/` بثلاث ملفات بنفس الاسم
(html/js/css) واتبع نفس نمط `src/pages/dashboard` بالظبط (شوفه كمرجع).

## ألوان وقياسات — ممنوع تكتب قيمة مباشرة

كل لون، مسافة، radius، خط لازم يجي من `assets/css/base/variables.css` عن
طريق `var(--…)`. **ممنوع نهائيًا** تكتب hex مباشر أو `px` ثابتة في أي ملف
تاني. لو محتاج قيمة مش موجودة، ضيفها في `variables.css` مرة واحدة وسمّيها
بنفس نمط التسمية الموجود (`--color-*`, `--space-*`, `--radius-*`, `--fs-*`).

هذا يضمن إن أي تعديل شكل (تغيير الأورانج مثلاً) يحصل في سطر واحد بدل ما
تدور في عشرات الملفات.

## التسمية

- ملفات ومجلدات: `kebab-case` (`stock-movement.js` مش `StockMovement.js`)
- كلاسات CSS: BEM خفيف — `.block`, `.block__element`, `.block.is-state`
  (زي `.stat-card`, `.stat-card__icon`, `.nav-link.is-active`)
- دوال JS: `camelCase`، ملفات modules بتصدّر functions مسماة، مفيش
  `default export` لأكتر من حاجة في نفس الملف عشان الـ tree-shaking/القراءة

## الراوتر والتحميل الكسول (Lazy Loading)

- الصفحات **ما تتحملش كلها مع بعض**. كل صفحة بتتحمّل بس لما المستخدم يدخلها
  عن طريق `router.js` باستخدام `import()` الديناميكي.
- أي صفحة جديدة لازم تتسجل في `PAGES` map جوه `router.js` بنفس الشكل
  (اسم المسار → دالة `() => import('../pages/x/x.js')`).
- ممنوع تضيف `<script>` تاني في `index.html` لأي صفحة — كل حاجة بتتحمل من
  جوه الراوتر بس. الـ shell (`index.html`) بيفضل خفيف طول الوقت.

## طبقة الـ API — ممنوع fetch مباشر جوه الصفحات

- أي طلب للباك اند لازم يعدّي من `src/core/api.js` بس. الصفحات بتنادي
  `api.get('/sales', {page, filters})` مش `fetch(...)` مباشرة.
- `api.js` هو المسؤول عن: base URL، الهيدرز، الـ cache، الـ error handling
  الموحد. أي تعديل في الـ base URL أو طريقة الاتصال يحصل في مكان واحد.
- البيانات شبه الثابتة (تصنيفات، مستخدمين، إعدادات) لازم تتكاش في
  `sessionStorage` عن طريق `api.js` نفسه، ومتتجابش تاني في نفس الجلسة إلا
  لو حصل تعديل (إضافة/حذف/تحديث) — في الحالة دي استدعي `api.invalidate(key)`.
- كل جدول فيه صفحات (pagination) لازم يبعت `page` و `pageSize` للباك اند —
  **ممنوع** تجيب كل البيانات وتقسمها في الفرونت.
- خانات البحث لازم تتلف بـ `debounce` من `utils.js` (350ms افتراضي) قبل
  ما تبعت أي request.

## الحالات الإلزامية لكل صفحة فيها بيانات

كل صفحة بتجيب بيانات من الـ API لازم تغطي الحالات الأربعة دي (زي التصميم
في فيجما بالظبط):

1. **Loading** — استخدم `.view-loading` / `.skeleton-row` الموجودين، ما
   تسيبش الشاشة فاضية.
2. **Success** — البيانات الحقيقية.
3. **Empty** — استخدم `.empty-state` مع نص واضح ("لا يوجد موردين بعد")
   وزرار الإجراء المناسب (زي "إضافة مورد جديد").
4. **Error** — استخدم `.error-state` مع زرار "إعادة المحاولة" بيعيد نفس
   الطلب، ونص خطأ واضح مش تقني.

## الاستجابة (Responsive) — إلزامي على كل عنصر جديد

فيه 3 breakpoints بس في `assets/css/layout/responsive.css`، ممنوع تضيف
`@media query` في ملف تاني غير الـ layout files أو ملف الصفحة نفسها لو
الحالة خاصة بيها بس:

- Desktop `> 1180px`: الوضع الكامل (سايد بار مفتوح بالنص)
- Tablet `768–1180px`: سايد بار أيقونات بس (شاشة الكاشير)
- Mobile `< 768px`: سايد بار drawer + جداول بـ scroll أفقي داخل
  `.table-responsive`

أي كومبوننت جديد (كارت، مودال، جدول) لازم يتفحص في التلات مقاسات قبل ما
يتعتبر خلص. جرب تصغير الشاشة فعليًا، متفترضش إنه هيشتغل لوحده.

## الأداء — قواعد صارمة

- ممنوع أي مكتبة خارجية تقيلة (Chart.js, jQuery...) — الرسوم البيانية
  (donut, line, bar) بتتعمل بـ SVG خفيف يتولد من JS، زي الموجود بالفعل.
- الصور: `loading="lazy"` إجباري على أي `<img>` مش فوق الطية مباشرة.
- ما تعملش DOM manipulation جوه loop من غير `DocumentFragment` لو العناصر
  كتير (جدول فيه صفوف كتيرة مثلاً).
- ملفات CSS الخاصة بصفحة معينة تتحمل مع الصفحة بس (`<link>` جوه الـ view
  template أو import عن طريق JS)، مش في `index.html` الرئيسي.

## قبل ما تقول "خلصت"

راجع الليستة دي قبل ما تسلّم أي تعديل أو صفحة جديدة:

- [ ] كل الألوان/المسافات جايه من `var(--…)` بدون قيم مباشرة
- [ ] الصفحة بتتحمل lazy عن طريق الراوتر، مش متضافة في `index.html`
- [ ] كل نداء API عدّى من `api.js`، وفيه cache/pagination/debounce حسب الحالة
- [ ] الحالات الأربعة (loading/success/empty/error) موجودة
- [ ] جرّبت الصفحة على 3 مقاسات (desktop/tablet/mobile) فعليًا
- [ ] مفيش كلاس CSS جديد بيكرر كلاس موجود بنفس الوظيفة
- [ ] أي نص جاي من مستخدم أو API بيتطبع بـ `escapeHtml()` لو داخل innerHTML
